# 工具网关：策略、审批、审计与凭据

> 总览见 [architecture.md](../architecture.md)，决议见 [roadmap.md](../roadmap.md)（#41、#42），路线节点 GW1。
>
> 借鉴：OpenBot 的「解析目标 → 判定策略 → 写审计 → 执行」单一入口；OpenMausBot 与 DS-Bot 的审批卡片；Memoh 的连接器网关与 DS-Bot 的连接器（Agent 拿不到原始凭据）。只借鉴设计，不引入代码。

## 1. 定位

Agent 做的事分两类：

| 类别 | 例子 | 走哪里 |
| --- | --- | --- |
| 工作目录内的操作 | 读写 workdir 里的文件、跑测试、构建 | 直接执行，受文件沙箱与禁用命令约束（[background.md §4](./background.md#4-隔离与安全)） |
| **有外部副作用的操作** | 推送代码、开 MR / PR、在 IM 发消息、发邮件、调用已连接的 SaaS、操作浏览器 | **必须经过工具网关** |

工具网关是这类操作的**唯一入口**。它属于**控制面**，不在执行沙箱里（roadmap #45）；沙箱的出口网络只通模型网关、工具网关与白名单依赖源，所以 Agent 在 shell 里也绕不过它。它不属于任何一个 Bot，团队 Bot 与个人 Bot 共用。

## 2. 一次调用的流程

```text
Agent 发起调用
  → 1 解析目标：哪个 Bot、哪个成员、对哪个外部系统做什么
  → 2 策略判定：允许 / 需要审批 / 拒绝
        需要审批 → 发审批卡片（应用、IM）→ 允许后继续；拒绝或超时则不执行
  → 3 写审计：谁、何时、对什么、判定结果、是否经人批准
  → 4 执行：网关用自己持有的凭据调用外部系统，把结果返回给 Agent
```

规则：

- **先判定，后执行**。判定服务不可用、策略加载失败、审计写不进去时，一律不执行（Fail-Closed）。
- **审计先于执行**。被拒绝的调用同样写审计。
- 同一次判定另外产生一条分析事件 `gateway.decided`（[logging.md §3](./logging.md#3-数据模型一个工单一条轨迹)）。它与审计分开存放：审计不可改、按合规保留；分析事件写不进去**不影响执行**，只计数。
- 网关对外部系统的底层接口不直接暴露给 Agent；Agent 无法绕过网关。

## 3. 策略

策略自上而下叠加，上层不能被下层放宽：

| 层 | 谁设置 | 内容 |
| --- | --- | --- |
| 内置基线 | 系统，不可关闭 | 永远需要审批或永远拒绝的动作（如删除仓库、修改权限、转账类操作） |
| 租户工具策略 | 租户管理员（[admin.md §4](./admin.md#4-租户管理后台)） | 允许接入的外部系统；各类动作默认是允许、需审批还是拒绝；拒绝规则 |
| Bot 权限预设 | 团队 Bot 由租户管理员、个人 Bot 由其所有者 | 这个 Bot 能用哪些连接器与工具 |

**判定分三档**（roadmap #49）。Mandate 是授权范围，工具网关是执行这个范围的地方：

| 情况 | 结果 |
| --- | --- |
| 读取类动作；或动作在当前工单的 **Mandate 范围内**（如在触发它的线程里回复、推送工作分支、为该工单开 MR / PR） | 放行，写审计 |
| 写入、发送、删除类动作，且不在 Mandate 范围内 | 审批卡片 |
| 命中内置基线 | 永远拒绝 |

租户可以把特定动作收紧为「总是审批」或「拒绝」，也可以把特定动作放宽为允许，但不能放宽内置基线。个人 Bot 的工单同样有 Mandate：所有者在对话里交代的事就是它的范围。

## 4. 审批卡片

- 需要审批的调用以**卡片**形式出现在发起它的会话里：应用会话，或 Bot 所在的 IM 线程。卡片写明谁要对什么做什么，以及具体内容（如要发送的消息正文、要推送的分支）。
- 可以批准的人：个人 Bot 的所有者；团队 Bot 则是触发该任务的成员或租户管理员。**Bot 账号不能批准**。
- 等待审批期间，Assignment 以 `reported{answer}` 结束并释放槽位，批准后以 `resume` 继续（沿用 [executor.md §5.4](../contracts/executor.md#54-人类交互模型无状态挂起--续跑) 的无状态挂起）。
- 超时无人处理视为拒绝，不执行。
- 支持「仅此一次」与「本任务内同类动作都允许」两种授权范围；不提供永久授权，永久放行只能由管理员改策略。
- 填写密钥的卡片不能在 IM 中完成，只能在应用里。

## 5. 凭据

- 连接器凭据（代码平台令牌、IM 应用密钥、邮箱授权、SaaS 授权）存放在密钥管理服务，**由工具网关持有，不注入 Agent 进程**，不出现在环境变量、Prompt、日志与事件中。
- Agent 只能通过网关提供的工具间接使用这些凭据，拿不到原始值。
- 凭据在界面上只写不读：保存后只显示「已配置」。
- `git` 拉取与推送通过网关签发的短期令牌完成，不把长期令牌放进 workdir。
- 模型凭据不经过工具网关，由租户模型网关处理（[background.md §6.1](./background.md#61-模型路由)）。

## 6. 本地执行

本地 Executor（`local_dir`）上的 Agent 调用**企业连接器**时同样走控制面的工具网关，凭据不下发到设备。只涉及用户本机的操作（本地文件、本机命令）由本地 Executor 自己的审批与沙箱处理，审批卡片照样出现在应用里。

各外部系统的具体默认策略在各自的集成文档里给出，GitLab 见 [gitlab.md §5](./gitlab.md#5-回复与变更请求)。
