# 管理后台设计

> 总览见 [architecture.md](../architecture.md)，落地顺序见 [roadmap.md](../roadmap.md)（节点 ADM0–ADM2，决议 #34）。

## 1. 定位与边界

系统分为两个面：

| 面 | 组成 | 职责 |
| --- | --- | --- |
| **数据面** | 入口网关、Bot 服务、工具网关、Executor（执行面）、租户模型网关 | 运行任务 |
| **管理面** | 本文描述的两个后台及其 API、共享层数据库 | 决定谁能用、能用什么、用了多少 |

管理面属于**共享层**，独立于 Bot 服务，原因有两个：

- 租户必须先存在，才能为它开通数据空间与执行配额。
- 用户登录之前，入口网关就要查到该租户的 SSO 配置，才知道按哪个租户处理。

管理后台有两个，面向不同的人：

| | 平台运营后台 | 租户管理后台 |
| --- | --- | --- |
| 使用者 | 我方运营人员 | 客户的租户管理员 |
| 入口 | 独立站点，只在 SaaS 部署 | 应用内的「管理」区，按角色显示 |
| 范围 | 所有租户 | 只有本租户 |
| 私有化部署 | 不交付（见 §7） | 交付 |

与应用控制台 Settings 的分工（[web-app.md §5.1](./web-app.md#51-标签页)）：

| 位置 | 管什么 | 数据在哪 |
| --- | --- | --- |
| 应用控制台 Settings | Bot 怎么工作：Sources、Eval、Execution、Prompts | Bot 服务 内 |
| 租户管理后台 | 租户本身：谁能登录、能用哪些模型、有哪些限制 | 共享层 |

两者都只有租户管理员能修改。

## 2. 角色

| 角色 | 范围 | 能做什么 |
| --- | --- | --- |
| **平台运营** | 全部租户 | 使用平台运营后台；**默认不能查看租户内容**（见 §3.1） |
| **租户管理员** | 本租户 | 使用租户管理后台；修改应用控制台 Settings；拥有成员的全部权限 |
| **成员** | 本租户 | 使用工作台与控制台（只读 Settings） |

- 角色只在应用与管理后台内生效。各 Source（GitHub、飞书等）的准入白名单仍由各 Source 自己维护，不与这里的角色映射（[bot.md §5.2](./bot.md#52-身份不跨-source-映射)）。
- 项目空间与会话在租户内是否共享，仍是待定问题（[web-app.md §7 第 5 题](./web-app.md#7-待定问题)）。

## 3. 平台运营后台

| 模块 | 功能 |
| --- | --- |
| 租户 | 开通、停用、恢复、删除；指定首个租户管理员（§6） |
| 租户开通与隔离档位 | 为租户开通数据空间、加密密钥、家目录卷与执行配额；选择隔离档位（默认 / 专属，roadmap #48，见 [runtime.md §2](./runtime.md#2-隔离)）；按租户灰度功能开关与执行内核版本，支持回滚 |
| 配额 | 每租户的并发 Assignment、Extra Slot、预览进程数、存储上限 |
| 用量与计费 | 每租户的模型用量、执行时长、存储；账单导出 |
| 全局健康 | Bot 服务与工具网关的健康状态（[bot.md §7](./bot.md#7-运维进程守护与故障自愈bot2) 的退出码）、云端 Executor 池负载、入口网关与模型网关状态 |
| 官方模板 | 发布与下架官方「专家」模板（[bot.md §8.1](./bot.md#81-bot-模板专家)） |
| 运营审计 | 运营人员自己的全部操作记录 |

### 3.1 运营人员与租户内容的隔离

- 运营人员能看到的是**元数据**：租户名称、运行状态、配额、用量数字、健康状态。
- **默认看不到租户内容**：会话、代码、日志、报告、Prompt、Source 凭据。
- **我方数据科学家同样受此约束**：只能使用不含原文的分析日志（L0 / L1，租户以去标识编号出现）；内容级日志（L2）须该租户开启「数据使用授权」（§4，roadmap #54，见 [logging.md §6](./logging.md#6-谁能看什么)）。
- 排障确需查看时走**应急访问**：由租户管理员授权，限定范围与时长，全程记录并对租户可见。
- 运营人员登录使用我方自己的 IdP，强制多因素认证，与租户 SSO 无关。

## 4. 租户管理后台

| 模块 | 功能 |
| --- | --- |
| SSO | 配置本租户的 IdP（OIDC / SAML）、登录域名、测试登录 |
| 成员与角色 | 查看通过 SSO 登录过的成员；设置管理员；停用成员。成员首次登录时为其开通家目录卷 |
| 模型目录 | 配置可用模型与上游凭据；按成员或角色开放；设置默认模型（[web-app.md §1.1](./web-app.md#11-模型来源)） |
| 策略开关 | 是否允许 BYOK、是否允许本地模型、是否允许本地执行 |
| 设备 | 查看已配对的桌面端设备（本地 Executor 的 `deviceId`、所属成员、最近在线时间）；吊销设备。配对流程见 [runtime.md §5](./runtime.md#5-手机经-bot-控制远程电脑) |
| 个人 Bot 可见范围 | 默认只看元数据（Bot 列表、用量、对外动作审计）；可开启「合规访问」，开启后对成员明示并留审计；成员离职后冻结 30 天再删除（roadmap #52，见 [runtime.md §7](./runtime.md#7-记忆)） |
| 数据使用授权 | 是否允许我方在受控分析环境中使用本租户的内容级日志（L2）改进产品；默认关闭；可只授权团队 Bot；个人 Bot 还需所有者本人同意；可随时撤回（roadmap #54，见 [logging.md §6](./logging.md#6-谁能看什么)）。是否参与实验分流 |
| 代码平台 | 添加与管理 GitLab / GitHub 连接：实例地址、Bot 身份令牌、接入的群组与项目；查看令牌到期日与 Webhook 状态（见 [gitlab.md §2、§8](./gitlab.md#2-接入租户管理员做一次)） |
| 工具策略 | 允许接入的外部系统；各类动作默认是允许、需审批还是拒绝；拒绝规则；是否要求团队 Bot 默认「独立」（见 [gateway.md §3](./gateway.md#3-策略)） |
| 安全规则 | 敏感文件的租户追加规则（[executor.md §7.3](../contracts/executor.md#73-文件浏览只读)）；禁用命令 |
| 用量 | 本租户的模型用量、并发占用、配额余量，可按成员查看 |
| 审计 | 准入裁决、Mandate 变更、人类指令、配置变更、登录与设备事件；可导出 |
| Bot | 创建、停用团队 Bot；把 Bot 设为「独立」（使用自己的卷）；查看各成员的个人 Bot 数量与资源占用，可设置数量上限 |
| 模板 | 管理租户内的「专家」模板（W4）。模板不携带凭据、对话、记忆与权限 |

规则：

- 上游模型凭据只写不读：保存后界面不再显示明文，存放于密钥管理服务。
- 关闭一个策略开关（如禁用 BYOK）立即对新派工生效；运行中的 Assignment 不被打断，但不能再续跑。
- 吊销设备后，该设备的长连接被断开，不能再注册；其上未结束的 Assignment 按 [executor.md §3.1](../contracts/executor.md#31-断线宽限期与对账) 的断线规则结算。
- 破坏性操作（删除模型、停用成员、吊销设备）一律二次确认，并写入审计。

## 5. 数据归属与配置下发

管理面的数据存放在共享层数据库（Postgres）：

| 数据 | 写入方 | 读取方 |
| --- | --- | --- |
| 租户登记、隔离档位、配额 | 平台运营后台 | 入口网关、Executor 池 |
| SSO 配置、成员、角色 | 租户管理后台 | 入口网关、应用 |
| 模型目录、策略开关、安全规则 | 租户管理后台 | 租户模型网关、Bot 服务、Executor |
| 设备登记 | 桌面端注册时写入，租户管理后台可吊销 | Bot 服务 |
| 用量、审计汇总 | Bot 服务 与模型网关上报 | 两个后台 |

管理面与数据面之间：

- **配置下发**：策略开关、模型目录、安全规则、配额由管理面推送给数据面各服务，各服务在本地缓存。
- **上报**：数据面把用量、审计记录、健康状态上报给管理面。
- **管理面不可达时**：数据面沿用最近一次缓存的配置继续工作。缓存超过有效期仍未更新时，限制类开关按更严格的一侧处理（如视为禁用 BYOK），不放宽。

## 6. 登录路由与首个管理员

登录流程：

```text
用户输入企业标识或邮箱 → 入口网关查到租户与 SSO 配置 → 跳转该租户的 IdP
  → 回调校验 → 查成员角色 → 进入应用，请求带上租户身份进入 Bot 服务
```

首个租户管理员的产生：

| 部署 | 方式 |
| --- | --- |
| SaaS | 运营开通租户时填写首个管理员的邮箱；系统发出一次性邀请链接，该管理员据此完成 SSO 配置，之后一律走 SSO 登录 |
| 私有化 | 安装时在配置文件中指定首个管理员与 SSO 配置 |

- 一次性邀请链接有有效期，用后作废。
- 租户至少保留一名管理员，不能把最后一名管理员降级或停用。
- **没有配置身份提供方时拒绝启动**，而不是把所有访问者当作管理员放行；单用户试用模式必须显式开启，且只监听本机（借鉴 OpenBot）。
- SSO 配置错误导致所有人无法登录时：SaaS 由运营重新签发邀请链接；私有化由运维通过命令行重置。

## 7. 私有化部署

- **不交付平台运营后台**。整套部署只有一个租户，租户在安装时由配置文件创建。
- 升级、重启服务、调整配额通过命令行与 Helm 完成（[deployment.md §4](./deployment.md#4-交付物节点-d1)）。
- 租户管理后台照常交付，功能与 SaaS 相同。
- 用量数据留在客户内网；是否上报给我方用于计费，取决于授权方式（[deployment.md §5 第 5 题](./deployment.md#5-待定问题)）。

## 9. 待定问题

1. **用量从哪里来**（DS-Bot 已在同一底座上做到按时间、按 Bot、按模型统计，可参考）：模型用量可以在租户模型网关统计；但本地执行使用 BYOK 或本地模型时不经过网关。是否需要在 Executor 契约的事件中增加用量字段？**已有方案**（roadmap #53）：契约新增 `activity` 事件，其中带 Token 用量；用量由分析日志的 L0 聚合得到，见 [logging.md §9](./logging.md#9-与其他部分的关系)。待定：自报的用量能否用于计费。
2. **是否需要更多角色**：如只读的审计员、只管模型与费用的角色。
3. **成员是否需要预先邀请**：现在是通过 SSO 登录即成为成员。是否要支持「只有被邀请的人才能进入」，或按 IdP 的用户组限制？
4. **租户删除后的数据保留**：租户数据、家目录卷、审计记录保留多久，是否提供导出？
5. **应急访问的授权粒度**：按工单、按时间段，还是按整个租户？

## 10. 实施要点

| 节点 | 任务 | 验收 | 风险与回退 |
| --- | --- | --- | --- |
| ADM0 | 编写 `docs/contracts/admin.md`；实现最小管理面：共享层数据库、命令行或配置文件完成租户创建、SSO 配置、首个管理员、租户开通；入口网关按租户路由 | 用命令行开通两个租户，各自经 SSO 登录后只能看到各自租户的数据，互相不可见 | 没有界面，只面向我方工程师 |
| ADM1 | 租户管理后台：应用内管理区，覆盖 §4 的模块 | 租户管理员能配置 SSO、模型目录与策略开关；禁用 BYOK 后新派工被 `MODEL_SOURCE_DISABLED` 拒绝；吊销设备后该设备无法再注册 | 用量与审计可以后于其他模块交付 |
| ADM2 | 平台运营后台：独立站点，覆盖 §3 的模块 | 运营能开通租户并签发首个管理员邀请；按租户灰度升级并回滚；运营账号无法读取任一租户的会话内容 | SaaS 对外开放多租户之前必须完成 |
