# SiriusX 任务步骤书

这份步骤书把 [roadmap.md](./roadmap.md) 决议 #61 的执行顺序展开成可以逐项打勾的任务。起点是 fork DSH Desktop，终点是桌面端、Web 端、手机端都可用。共 11 步，S0 到 S10，先本地后云端，最后扩到全平台。每一步都有验收标准，验收不过不进入下一步。

## 怎么读这份步骤书

一个方框是一件事。方框后面写着用什么证据来勾它，证据是一个文件、一段抓包记录、一次测试运行、一张截图或一个提交号。没有证据就不打勾。

每一步有四块，顺序固定：

- **前置**：开工前必须已经成立的条件。
- **任务**：要做的事。
- **验收标准**：判定这一步做完的条件。每一条都要在真实产物上检查，测试通过不算数，要实际跑一遍、看一眼、抓一次包。
- **产出物**：这一步留下的东西。

证据统一存到 `evidence/S<编号>/`，文件名用验收条目的序号开头，例如 `evidence/S1/03-network-capture.har`。

正文只讲怎么做。为什么这样排、否决了什么方案、有什么风险，放在附录。

## 全程规则

这四条对每一步都生效，每一步的验收都默认包含它们。

- [ ] **fork 只动外壳。** 对上游的改动只落在 `apps/desktop` 下。证据：`git diff --stat <上游标签>` 的输出，改动文件数是个位数。
- [ ] **只 rebase 不 merge。** 上游是单独一个 remote，我方分支每季度 rebase 一次。证据：分支历史是线性的。
- [ ] **从 S5 起始终能单机一体安装。** 每加一个服务，安装脚本同步更新。证据：安装脚本在一台干净机器上跑通的日志。
- [ ] **权限只在服务端判定。** 界面插件只负责显示。证据：改掉本机插件的启用状态后，服务端仍然拒绝请求的记录。

## 验证四个前提（S0）

**前置。** 无。

**任务。**

- [ ] 把上游仓库 `deepseek-ai/deepseek-harness` clone 到本机，记下所用的标签。证据：标签名与提交号。
- [ ] 读 `apps/desktop` 的主进程、preload、Host 启动与认证链路，回答下面四个问题。每个问题给出「能」「不能」或「有条件」的结论。
  - [ ] Host 的认证能否以插件方式替换成 SSO，还是必须改 Host 源码。证据：认证入口的文件路径与行号。
  - [ ] 租户上下文怎么进入 Host。证据：主进程携带认证信息的代码位置，以及一个把自定义字段带进 Host 的最小实验。
  - [ ] Executor 插件与界面前端能否在同一个 Host 里并存。证据：一个最小插件在界面开着时调用内核跑完一轮的日志。再记录同一个会话被界面和插件同时操作时发生了什么。
  - [ ] dsh-TUI 的 `src/agent` 接口与 DSH 后端能否拆出来。证据：把它们拷进一个空包后类型检查通过的输出，以及为此替换或带走的类型清单。
- [ ] 写出施工图 `docs/spike.md`。

**验收标准。**

- [ ] 四个问题各有结论，每个结论都指向源码位置或可重跑的实验。
- [ ] 施工图列出 fork 要改的每一个文件，并给出文件总数。
- [ ] 如果第一个问题的结论是「必须改 Host 源码」，已经更新 roadmap #56，并把 S5 拆成两步写回本文件。

**产出物。** `docs/spike.md`，`evidence/S0/` 下的实验记录。

## 跑通本机闭环（S3）

**前置。** S1 与 S2 完成。

**任务。**

- [ ] 把 Executor 写成 Host 内的插件，实现契约的 `local_dir`，经内核接口进程内调用 dsh。
- [ ] 在 Executor 里实现结构化报告、`diffStats`、workdir 管理，这些不在内核接口里。
- [ ] 让 Bot 服务以单租户加 SQLite 的形态跑在本机，包含 Engine、Outbox、阶段推导、打断防抖。这份代码在 S5 原样搬到云端，只换部署位置。
- [ ] 提供一个最简单的派工入口，命令行即可。
- [ ] 录制三到五段真实任务的会话日志，作为内核升级时的回归基线。

**验收标准。** 以下每条都在一个真实的代码目录上执行，证据是事件流记录加终端录屏。

- [ ] 派一个任务，它经过 `running` 到 `ready`，报告里带 `diffStats`，数字与 `git diff --stat` 一致。
- [ ] 任务运行中追加一句话。任务先被 graceful cancel，再在同一个会话里 resume 并把活干完。
- [ ] agent 中途提问。本次派工以 `answer` 报告结束，回答后的新派工接着同一个会话继续。
- [ ] 任务运行中杀掉 Host。15 分钟内重启后状态对账正确，没有重复事件推进工单。
- [ ] 回收 workdir 后，用户指定的目录还在，只有 Executor 自己建的 worktree 和临时目录被清掉。
- [ ] S2 的场景剧本里适用于 `local_dir` 的那些，对着真实 Executor 全部通过。证据：逐场景输出，并列出不适用的场景及原因。
- [ ] 界面开着的同时 Executor 在跑任务，两边互不干扰。
- [ ] 以上全部通过后，给契约打一个版本标签。此后改契约要走变更评审。这是里程碑 M1。

**产出物。** Executor 插件，本机 Bot 服务，回归用的会话日志，契约版本标签。

**检查点。** 这一条不过，就回头改 S2 到 S4，不进入 S5。

- [ ] 本人连续 10 个工作日用工单界面做真实工作，其中至少 8 天有经工单完成的真实任务。证据：每天一行的记录，写明任务、是否走工单、没走的原因。

**产出物。** 应用契约的类型包，四个界面插件，使用记录。

## 接入登录与组织管理（S5）

**前置。** S4 检查点通过。S0 关于 SSO 的结论决定这一步的做法。

**任务。**

- [ ] 把 Bot 服务部署到一台服务器上，支持多个用户，数据按租户隔离并各自加密。
- [ ] 提供命令行开通租户：创建租户、配置 SSO、指定首个管理员。
- [ ] 在桌面端接入 SSO 登录，协议先做 OIDC。
- [ ] 让租户上下文进入 Host，做法以 S0 的结论为准。
- [ ] 做入口网关的最小版：本机 Executor 主动建立长连接，网关按租户路由。
- [ ] 做租户模型网关的最小版：本机 dsh 用 SSO 短期令牌访问，上游密钥留在服务端。
- [ ] 做设备配对：桌面端显示配对码，成员在已登录的界面里确认。
- [ ] 做个人 Bot 的最小版：成员能创建一个个人 Bot，它能派工给该成员已配对的电脑。本地执行只给个人 Bot（#51）。
- [ ] 登录后给原生对话标上「个人、不审计」，并提供租户管理员关闭它的开关。
- [ ] 写单机一体的安装脚本，把以上服务装到一台机器上。

**验收标准。**

- [ ] 用命令行开通两个租户。两个租户的成员各自经 SSO 登录后，只能看到自己租户的数据。证据：两边的截图与服务端访问日志。
- [ ] 不登录时只有原生对话。此时直接请求 Bot 服务的接口，服务端拒绝。证据：请求与响应记录。
- [ ] 登录后原生对话带有「个人、不审计」标识。管理员关掉开关后，登录状态下原生对话入口不可用。证据：开关前后的截图。
- [ ] 未配对的设备和已吊销的设备都建立不了长连接。证据：网关日志。
- [ ] 在本机抓包并搜索磁盘，找不到模型上游密钥。证据：抓包文件与搜索命令的输出。
- [ ] 断网后 15 分钟内恢复，本地任务的状态对账正确。断网超过 15 分钟，工单被结算为 `lost`。证据：两种情况的事件流记录。
- [ ] 手工改掉本机插件的启用状态，让团队面板在未登录时显示出来。面板里没有数据，服务端拒绝了它的请求。证据：截图与服务端日志。
- [ ] 安装脚本在一台干净机器上跑通，装完后以上各条在这台机器上重新验一遍全部通过。证据：安装日志与复验记录。

**产出物。** 云端 Bot 服务，两个网关的最小版，开通租户的命令行，安装脚本。

## 附录 A. 还没验证的前提

这份步骤书建立在下面这些前提上，它们都还没有验证，对应的验证任务写在括号里。

- 同一个安装包登录后变成企业版，这要求 SSO 和租户上下文能进入 Host（S0）。
- Executor 能作为 Host 内的插件与界面并存（S0）。
- dsh-TUI 的内核接口和 DSH 后端能拆出来单独使用（S0）。
- `pi-acp` 支持我们要用的四个调用（S7 开工前）。
- DSH 的 `web` profile 能在云端按用户提供同一套前端（S9 开工时）。
- 响应式 Web 足以覆盖手机端的两个场景（S10 开工时）。

## 附录 B. 否决的排法

- **先云端沙箱，再 Bot，最后应用。** 这是原路线的顺序。否决的原因是云端沙箱的工作不影响契约，却把第一次真实使用推到很后面。
- **开工前把七个待验证问题一次验完。** 否决的原因是其中三个要到 S7 和 S9 才用得上，提前验会拖慢开工。
- **S1 就把品牌、签名、更新源做完。** 否决的原因是它们对验证产品没有帮助，并且每次 rebase 都要多处理一遍。
- **Bot 服务放到最后做。** 否决的原因是本地 Executor 和工单界面都需要有东西派工、有工单可显示。
- **内核统一走 ACP。** 被 #57 的统一内核接口取代，ACP 降为接入方式之一。
